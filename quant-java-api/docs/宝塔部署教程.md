# 宝塔面板部署教程（Ubuntu 24.04 + MySQL 8 + Redis）

> 目标：把 `quant-java-api`（后端 + 内置管理后台）部署到宝塔服务器，对外提供
> `http://<服务器IP>:8080` 的 iOS 接口与 `http://<服务器IP>:8080/panel` 的管理后台。
> 本文以实测服务器 `154.12.16.204` 为例。

---

## 0. 环境清单

| 组件 | 版本 / 路径 |
| --- | --- |
| 系统 | Ubuntu 24.04 LTS（4 核 / 4 GB） |
| 宝塔面板 | 13.1（示例端口 `8888`，安全入口 `/5d94babc`） |
| JDK | `/www/server/java/jdk-21.0.2`（宝塔 Java 项目管理器自带） |
| Maven | `/opt/maven`（3.9.9，可选：仅服务器构建时需要） |
| Node | `/opt/node`（20.x，可选：仅服务器构建前端时需要） |
| MySQL | 8.0.45（宝塔软件商店安装，`127.0.0.1:3306`） |
| Redis | 6.x（宝塔软件商店安装，`127.0.0.1:6379`） |
| 后端 jar | `/opt/quantokx-java/app.jar` |
| systemd 服务 | `quantokx-java`（监听 `8080`） |

## 1. 安装运行环境

### 1.1 宝塔安装 MySQL 8 与 Redis

宝塔面板 → **软件商店** → 搜索并安装：

- **MySQL 8.0**（不要选 5.7）
- **Redis**

> 若已装 MySQL 5.7，需先在宝塔软件商店卸载（或命令行 `sh /www/server/panel/install/mysql.sh uninstall 5.7`），
> 再安装 8.0。注意：卸载会清空数据，请先备份。

命令行安装 MySQL 8.0（宝塔脚本，会重置数据目录并生成随机 root 密码）：

```bash
# 先确保没有 mysqld 在运行
/etc/init.d/mysqld stop 2>/dev/null; pkill -9 -x mysqld; pkill -9 -x mysqld_safe
nohup sh /www/server/panel/install/mysql.sh install 8.0 > /root/mysql80.log 2>&1 &
tail -f /root/mysql80.log
```

安装完成后把 root 密码设为已知值（宝塔命令行第 7 项）：

```bash
printf "7\nRoot@Amore2026\n" | bt
mysql -uroot -p'Root@Amore2026' -e "select version()"
```

### 1.2 JDK 21 / Maven / Node

```bash
# JDK 21（宝塔 Java 项目自带）
/www/server/java/jdk-21.0.2/bin/java -version

# Maven（仅服务器构建需要）
cd /opt && curl -sSL -o mvn.tgz https://archive.apache.org/dist/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.tar.gz \
  && tar xzf mvn.tgz && mv apache-maven-3.9.9 /opt/maven

# Node 20（仅服务器构建前端需要）
cd /opt && curl -sSL -o node.tar.xz https://nodejs.org/dist/v20.18.0/node-v20.18.0-linux-x64.tar.xz \
  && tar xJf node.tar.xz && mv node-v20.18.0-linux-x64 /opt/node
export PATH=/opt/node/bin:$PATH
node -v && npm -v
```

### 1.3 放行 8080 端口

```bash
ufw allow 8080/tcp comment 'Amore backend + admin console'
ufw reload
ufw status | grep 8080
```

> 宝塔面板 → 安全 → 也需放行 `8080`。

## 2. 建库与建用户

```bash
mysql -uroot -p'Root@Amore2026' <<'SQL'
CREATE DATABASE IF NOT EXISTS quantokx DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'quantokx'@'127.0.0.1' IDENTIFIED BY 'AmoreDb@2026';
CREATE USER IF NOT EXISTS 'quantokx'@'localhost' IDENTIFIED BY 'AmoreDb@2026';
ALTER USER 'quantokx'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY 'AmoreDb@2026';
ALTER USER 'quantokx'@'localhost' IDENTIFIED WITH mysql_native_password BY 'AmoreDb@2026';
GRANT ALL PRIVILEGES ON quantokx.* TO 'quantokx'@'127.0.0.1';
GRANT ALL PRIVILEGES ON quantokx.* TO 'quantokx'@'localhost';
FLUSH PRIVILEGES;
SQL

# 验证
mysql -uquantokx -p'AmoreDb@2026' -h127.0.0.1 quantokx -e "select database(), version()"
```

## 3. 导入数据库脚本

仓库 `quant-java-api/db/schema.sql` 含 26 张表 + 种子数据（默认管理员、角色、系统配置、版本号）：

```bash
mysql -uquantokx -p'AmoreDb@2026' -h127.0.0.1 quantokx < /root/schema.sql

# 校验
mysql -uquantokx -p'AmoreDb@2026' -h127.0.0.1 quantokx -N -e \
  "select count(*) from information_schema.tables where table_schema='quantokx'"   # 期望 26
```

> 也可跳过本步：应用首次启动时 `SchemaBoot` 会自动建表并写入种子数据（幂等）。

## 4. 构建 jar

### 方式 A：服务器上构建（推荐，无需本地环境）

```bash
export JAVA_HOME=/www/server/java/jdk-21.0.2
export PATH=/opt/maven/bin:/opt/node/bin:$JAVA_HOME/bin:$PATH

# 1) 构建前端（产物输出到 ../quant-java-api/src/main/resources/static/panel）
cd /root/build/admin-web
npm config set registry https://registry.npmmirror.com
npm install --no-audit --no-fund
npm run build

# 2) 打包后端（前端产物会被打进 jar）
cd /root/build/quant-java-api
mvn -DskipTests package
ls -la target/*.jar
```

### 方式 B：CI 构建

推送到 `main` 或打 tag `quant-java-v*`，GitHub Actions（`.github/workflows/quant-java-api.yml`）
会自动构建前端 + 后端并上传产物 / 发 Release，从 Release 下载 jar 即可。

## 5. 部署与 systemd

```bash
mkdir -p /opt/quantokx-java/data
cp /root/build/quant-java-api/target/quant-java-api-2.0.0.jar /opt/quantokx-java/app.jar

# 环境变量文件
cat > /opt/quantokx-java/app.env <<'EOF'
DB_URL=jdbc:mysql://127.0.0.1:3306/quantokx?useUnicode=true&characterEncoding=UTF-8&serverTimezone=UTC&useSSL=false&allowPublicKeyRetrieval=true
DB_USER=quantokx
DB_PASSWORD=AmoreDb@2026
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
ADMIN_JWT_SECRET=<用 openssl rand -hex 32 生成>
ADMIN_INIT_PASSWORD=Admin@2026
EOF
chmod 600 /opt/quantokx-java/app.env
```

```bash
cat > /etc/systemd/system/quantokx-java.service <<'EOF'
[Unit]
Description=Amore iOS App Backend + Admin Console
After=network.target mysqld.service redis-server.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/quantokx-java
EnvironmentFile=/opt/quantokx-java/app.env
ExecStart=/www/server/java/jdk-21.0.2/bin/java -Xms256m -Xmx768m -jar /opt/quantokx-java/app.jar
Restart=always
RestartSec=5
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable quantokx-java
systemctl restart quantokx-java
```

## 7. 从旧 SQLite 版本升级（仅老部署需要）

```bash
systemctl stop quantokx-java
cp /opt/quantokx-java/data/qk.db /opt/quantokx-java/data/qk.db.bak     # 先备份

cd /opt/quantokx-java
DB_URL="jdbc:mysql://127.0.0.1:3306/quantokx?useUnicode=true&characterEncoding=UTF-8&serverTimezone=UTC&useSSL=false&allowPublicKeyRetrieval=true" \
DB_USER=quantokx DB_PASSWORD=AmoreDb@2026 \
/www/server/java/jdk-21.0.2/bin/java -jar app.jar --migrate --sqlite=/opt/quantokx-java/data/qk.db

systemctl start quantokx-java

# 校验行数（与旧库对比）
mysql -uquantokx -p'AmoreDb@2026' -h127.0.0.1 quantokx -e \
  "select (select count(*) from users) users, (select count(*) from chat_sessions) sessions;"
```

迁移特性：保留原主键；`users` 表补齐新列（`created_at` 取迁移时刻、`status=1`、`nickname=用户名`）；
密码哈希 `$qk$12000$salt$hash` 原样搬运，**老用户可直接登录**；脚本幂等（重复执行先清空目标表再导入）。

## 8. 安全加固

```bash
# 1) 生成强 JWT 密钥
openssl rand -hex 32        # 填入 app.env 的 ADMIN_JWT_SECRET

# 2) 修改默认管理员密码（登录面板 → 右上角 → 修改密码）

# 3) MySQL / Redis 仅监听本机（宝塔默认已满足）
ss -ltn | grep -E '3306|6379'   # 应为 127.0.0.1

# 4) 防火墙最小放行
ufw status
```

- 生产建议启用 HTTPS：宝塔 → 网站 → 反向代理到 `127.0.0.1:8080` 并申请证书，之后用 `https://域名/panel` 访问。
- `app.env` 权限保持 `600`，不要提交到版本库。

## 9. 日常运维

```bash
# 查看日志
journalctl -u quantokx-java -f
journalctl -u quantokx-java -n 200 --no-pager

# 重启 / 停止
systemctl restart quantokx-java
systemctl stop quantokx-java

# 更新版本：替换 jar 后重启
cp 新jar /opt/quantokx-java/app.jar && systemctl restart quantokx-java
```

数据库每日备份（宝塔计划任务或 crontab）：

```bash
# 每天 3:30 备份，保留 14 天
30 3 * * * mysqldump -uquantokx -p'AmoreDb@2026' -h127.0.0.1 quantokx | gzip > /root/backup/quantokx_$(date +\%F).sql.gz
0 4 * * * find /root/backup -name 'quantokx_*.sql.gz' -mtime +14 -delete
```

## 10. 常见问题排查

| 现象 | 排查与解决 |
| --- | --- |
| 外网打不开 8080 | `ufw allow 8080/tcp`；宝塔安全组放行；`ss -ltnp \| grep 8080` 确认监听 |
| 启动即退出（Unknown time-zone ID: SYSTEM） | `DB_URL` 里 `serverTimezone` 必须是 `UTC`（或 `Asia/Shanghai`），不能写 `SYSTEM` |
| 连不上 MySQL | 检查 `app.env` 的账号密码；`mysql -uquantokx -p -h127.0.0.1 quantokx`；确认库与授权已建 |
| `interval` 语法错误 | 属旧代码问题，v2.0 已对保留字加反引号；确认部署的是最新 jar |
| Redis 挂了 | 后端自动降级为内存会话，服务不中断，仅重启后登录态丢失；修复 Redis 后自动恢复 |
| 登录报「未登录或会话已过期」 | iOS 侧需先 `ping` 拿 Cookie；Web 后台需带 `Authorization: Bearer` |
| CSRF 校验失败（419） | 写请求未带 `X-CSRF-TOKEN`，token 取自 `ping`/`login` 响应 |
| 时区不一致 | 服务器为 UTC，历史数据亦为 UTC，**不建议改时区**，否则新旧数据时间会错位 |
| 端口被占用 | `ss -ltnp \| grep 8080`，停掉占用进程或改 `server.port` |
| 面板 404 | 前端产物未打进 jar：确认 `src/main/resources/static/panel/index.html` 存在后重新 `mvn package` |
